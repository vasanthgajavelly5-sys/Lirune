# Lirune Reader Provenance and License Audit

Date: 2026-10-01

## Scope and Confidence

This is a repository-level audit of declared dependencies, committed notices, generated assets, and obvious vendored sources. Installed package license metadata and upstream package repositories were not replaced by assumptions. Confidence is high for declared package provenance and medium for every generated/corpus asset until the release artifact is inspected.

| Source/artifact | License/provenance | Usage | Required action | Status |
|---|---|---|---|---|
| Expo/RN application code under `mobile/` | Project-authored; repository root is GPL-3.0-only per project docs | App, state, readers, services | Preserve project license and authorship | Reviewed |
| `jszip` 3.10.x | MIT; npm package with lockfile integrity | EPUB/ZIP extraction | Keep notice and monitor security updates | Compatible |
| `pdfjs-dist` 3.11.x | Apache-2.0; generated by `scripts/gen-pdfjs.js` from installed package | Vendored PDF.js source/worker | Preserve Apache notice; upgrade only with a tested generated-asset pipeline; audit high advisory | Action required |
| `pdfjsAssets.ts` | Generated output, not hand-authored | Offline PDF WebView | Regenerate only from a pinned dependency and verify hashes | Reviewed |
| `expo-file-system`, `expo-document-picker`, `expo-sqlite`, `expo-speech`, `expo-router`, vector icons | Upstream Expo licenses; package-manager metadata is authoritative for exact transitive set | Native/runtime services | Preserve installed notices in release process | Compatible pending release notice export |

## Findings

1. The root third-party notice mentions `epubjs` and Electron even though the mobile package uses JSZip and native Expo services. This is confusing and should be split into mobile and desktop notices.
2. The mobile `LICENSE` file contains an Expo MIT notice, not the project's stated GPL-3.0-only license. This is a distribution/compliance discrepancy requiring legal-owner confirmation before release.
3. The PDF.js generated-source license header is preserved by the generator, which is good, but the exact installed package version and advisory status must be recorded in release notices.
4. Dictionary and font provenance are not sufficiently documented to make a final redistribution determination.
5. No evidence of unauthorized copied implementation was found in the files sampled, but several parser implementations are heuristic and should not be represented as upstream code.

## Required Remediation

- Replace the ambiguous mobile `LICENSE`/notice arrangement with the correct project license plus preserved third-party notices.
- Add a generated mobile third-party inventory from `package-lock.json` and installed package license metadata.
- Document dictionary/font sources and licenses or remove assets whose redistribution rights cannot be established.
- Keep PDF.js attribution and license text with the generated bundle.
- Do not remove legitimate upstream copyright notices.
